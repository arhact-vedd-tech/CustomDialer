# Спека: поток исходящего вызова

Ядро системы. Всё остальное — UI поверх этого.

## Точки входа

| Триггер | Путь |
|---|---|
| Dialer: ввод + «Позвонить» | `DialerViewModel` → `OutgoingCallOrchestrator.dial(number, sim)` |
| T9: тап по контакту | то же, `number` из контакта |
| Call Log: тап по записи | то же, `number` из `CallLog.Calls.NUMBER` |
| Избранное: свайп | то же |
| Повтор из уведомления | то же |
| Внешний intent `ACTION_DIAL` / `ACTION_CALL` | `DialerActivity` → orchestrator |

Все пути сходятся в один оркестратор. Дублирования логики нет.

## Пошаговый поток

```
[1] Ввод номера
     │
     ▼
[2] Нормализация
     │
     ▼
[3] Проверка исключений ──► совпало ──► [8] placeCall (как есть)
     │ нет
     ▼
[4] Проверка белого списка ──► совпало ──► применить правило X ──► [7]
     │ нет
     ▼
[5] Матчинг правил (first-match по priority)
     │
     ├── ни одно не совпало ──► [8] placeCall (как есть)
     │
     └── совпало правило R ──► [6] Полуавто? ──► да ──► bottom sheet выбора
     │                                              │
     │                                              ├── «Напрямую» ──► [8]
     │                                              └── «Правило R» ──► [7]
     ▼ нет
[7] Трансформация номера (STRIP / PREPEND / STRIP_PREPEND + паузы)
     │
     ▼
[8] placeCall через TelecomManager
     │
     ▼
[9] Ожидание CallRedirectionService (системный вызов)
     │
     ▼
[10] Запись CallLog: исходный номер
     │
     ▼
[11] Запись CallLogExtras: appliedRuleId, dialedNumber
```

## Детали по шагам

### [2] Нормализация

| Действие | Правило |
|---|---|
| Удаление пробелов, дефисов, скобок | всегда |
| `+7` / `8` — не трогать на этом шаге | это работа правил, не нормализации |
| `,` и `;` — сохранить | это DTMF-паузы, часть номера |
| Пустая строка после очистки | отказ, тост «Некорректный номер» |

### [3] Исключения

Проверка: точное совпадение номера ИЛИ номер принадлежит контакту с меткой из исключений. Залоченные (`112`, `101`, `102`, `103`) — всегда в списке.

### [4] Белый список

Точное совпадение номера ИЛИ метка контакта. Применяется правило X, минуя приоритет.

### [5] Матчинг

- Условия правила — **AND**. Все должны совпасть.
- Типы: `LENGTH` (равно N), `STARTS_WITH` (префикс), `LABEL` (метка контакта).
- `simSlot` — если задан, правило применяется только к этой SIM.
- First-match по возрастанию `priority`. Первое совпавшее — стоп.
- Отключённые правила (`enabled = false`) пропускаются.

### [6] Полуавто

Bottom sheet: «Напрямую» / «Правило R» / (если матчей несколько — все подходящие). Показывается только если правило помечено как полуавтоматическое. Автоматические — без диалога.

### [7] Трансформация

| Action | Логика |
|---|---|
| `STRIP` | убрать N первых цифр |
| `PREPEND` | вставить префикс в начало |
| `STRIP_PREPEND` | сначала strip, потом prepend |
| Паузы | `,` и `;` остаются в строке как есть — Telecom их интерпретирует |

Результат — строка для `placeCall`. Если после трансформации пусто — отказ, тост, вызов не уходит.

### [8] placeCall

```kotlin
val handle = resolvePhoneAccount(simSlot) // PhoneAccountHandle
val uri = Uri.fromParts("tel", transformed, null)
val extras = Bundle().apply {
    putParcelable(TelecomManager.EXTRA_PHONE_ACCOUNT_HANDLE, handle)
}
telecomManager.placeCall(uri, extras)
```

`resolvePhoneAccount`: если `simSlot` задан — искать по `PhoneAccountHandle` с нужным slot; если нет — дефолтный.

### [9] CallRedirectionService

Система вызывает `onPlaceCall` в нашем `CallRedirectionService`. Здесь:

- Подтверждаем номер (он уже трансформирован на шаге 7).
- Возвращаем `redirectCall()` или `cancelCall()`.
- Таймаут — 5 сек. Зависание = сброс вызова.

**Важно:** трансформация делается **до** `placeCall`, в шаге 7. `CallRedirectionService` — страховка и точка для системных правил, не место для нашей логики. Иначе двойная трансформация.

### [10]–[11] CallLog

Пишем в системный `CallLog` **исходный** номер (шаг 1, нормализованный). В `CallLogExtras` — `appliedRuleId`, `dialedNumber` (трансформированный), `originalNumber`.

Связь: `CallLogExtras.callLogId` = `CallLog.Calls._ID` только что созданной записи. Запись — после `placeCall`, асинхронно, в `Dispatchers.IO`.

## Точки отказа

| Шаг | Отказ | Поведение |
|---|---|---|
| 2 | пустой номер | тост, стоп |
| 5 | правило-конфликт (два правила с одинаковым priority) | лог-варнинг, применяется первое попавшееся; в UI редактора — валидация уникальности |
| 7 | пустой результат | тост, стоп |
| 8 | нет `PhoneAccountHandle` для SIM | тост «SIM недоступна», стоп |
| 8 | `SecurityException` (нет `CALL_PHONE`) | редирект на onboarding |
| 9 | таймаут `CallRedirectionService` | система сбрасывает вызов; в лог |
| 10 | `CallLog` write fail | вызов уже ушёл; `CallLogExtras` пишем без `callLogId` (orphan), лог |

## Что НЕ входит в поток

- Входящие — отдельный путь через `InCallService.onCallAdded`.
- Конференция — `InCallService` merge, не пересекается с префиксами.
- Быстрые кнопки ручного режима — это shortcut в шаг 7, не отдельный поток.
