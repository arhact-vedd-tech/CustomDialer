# Спека: разрешения

## Принцип

Корпоративное приложение, Play не используется → нет Permissions Declaration Form. Но runtime-разрешения и роль Dialer запрашиваются как обычно. Логика: **минимум в manifest, запрос — в контексте, отказ — с деградацией, а не блокировкой.**

## Manifest

| Разрешение | Зачем | Уровень |
|---|---|---|
| `READ_CALL_LOG` | чтение журнала | dangerous |
| `WRITE_CALL_LOG` | запись исходного номера, `CallLogExtras` | dangerous |
| `READ_CONTACTS` | T9, карточки, метки | dangerous |
| `CALL_PHONE` | `placeCall` fallback | dangerous |
| `ANSWER_PHONE_CALLS` | приём входящих через `InCallService` | dangerous |
| `READ_PHONE_STATE` | SIM, `PhoneAccountHandle` | dangerous |
| `POST_NOTIFICATIONS` | heads-up, foreground service | dangerous (API 33+) |
| `USE_FULL_SCREEN_INTENT` | full-screen incoming | normal (special на 34+) |
| `FOREGROUND_SERVICE` | foreground service | normal |
| `FOREGROUND_SERVICE_PHONE_CALL` | тип FGS для звонков | normal |
| `MANAGE_OWN_CALLS` | self-managed calls (если понадобится) | normal |
| `READ_PHONE_NUMBERS` | номер своей SIM (опционально) | dangerous |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | опционально, по запросу | normal (special) |

## Роль Dialer

| Шаг | API | Условие |
|---|---|---|
| Проверка доступности | `RoleManager.isRoleAvailable(ROLE_DIALER)` | всегда |
| Проверка текущего держателя | `RoleManager.isRoleHeld(ROLE_DIALER)` | всегда |
| Запрос | `RoleManager.createRequestRoleIntent(ROLE_DIALER)` → `startActivityForResult` | если не held |

Роль запрашивается **первой**, до runtime-разрешений. Без роли остальное бессмысленно.

## Тайминг запросов

| Этап | Что запрашивается | Условие показа |
|---|---|---|
| Onboarding шаг 1 | `ROLE_DIALER` | всегда |
| Onboarding шаг 2 | `READ_PHONE_STATE`, `READ_CONTACTS`, `READ_CALL_LOG`, `WRITE_CALL_LOG`, `CALL_PHONE`, `ANSWER_PHONE_CALLS` | после роли |
| Onboarding шаг 3 | `POST_NOTIFICATIONS` (API 33+), `USE_FULL_SCREEN_INTENT` (API 34+) | после шага 2 |
| Первый входящий | — | система сама, через `InCallService` |
| Настройки → батарея | `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | по явному запросу пользователя |

Правило: **не запрашивать всё сразу одним пакетом.** Группами по смыслу, с объяснением перед каждым запросом (rationale-экран, не системный диалог).

## Деградация при отказе

| Отказано | Поведение |
|---|---|
| `ROLE_DIALER` | баннер в Dialer «Приложение не является звонилкой по умолчанию», кнопка «Запросить». Базовый набор работает, входящие — нет. |
| `READ_CALL_LOG` / `WRITE_CALL_LOG` | журнал пуст, бейдж «нет доступа». Вызовы работают. `CallLogExtras` пишется без `callLogId` (orphan). |
| `READ_CONTACTS` | T9 по номерам, без имён и фото. Метки недоступны → правила по LABEL не работают, в редакторе — предупреждение. |
| `CALL_PHONE` | `placeCall` через `ACTION_CALL` intent (системный диалог). |
| `ANSWER_PHONE_CALLS` | входящие показывает система, наш In-Call UI не поднимается. |
| `POST_NOTIFICATIONS` | heads-up не показывается, только full-screen при заблокированном. |
| `USE_FULL_SCREEN_INTENT` | входящий — только heads-up, full-screen нет. |
| `READ_PHONE_STATE` | SIM-селектор скрыт, правила по `simSlot` не применяются. |

Ни один отказ не блокирует приложение полностью. Деградация — видимая, с путём восстановления через Настройки.

## Rationale-экраны

Перед системным диалогом — короткий экран с объяснением:

| Разрешение | Текст |
|---|---|
| `READ_CALL_LOG` | «Нужен доступ к журналу, чтобы показывать историю и сохранять исходные номера без префикса.» |
| `READ_CONTACTS` | «Нужен доступ к контактам для поиска по T9 и меток для правил префиксов.» |
| `ANSWER_PHONE_CALLS` | «Нужен доступ, чтобы показывать экран входящего вызова.» |
| `POST_NOTIFICATIONS` | «Нужен для уведомлений о входящих звонках.» |

Кнопки: «Разрешить» → системный диалог, «Не сейчас» → пропуск, «Зачем это?» → развёрнутый текст.

## Состояния разрешений

```kotlin
sealed class PermissionState {
    object Granted : PermissionState()
    object Denied : PermissionState()          // можно запросить снова
    object PermanentlyDenied : PermissionState() // только через настройки
    object NotApplicable : PermissionState()   // API < требуемого
}
```

`PermanentlyDenied` определяется через `shouldShowRequestPermissionRationale == false` после отказа + `checkSelfPermission != GRANTED`.

## Проверка при старте

| Момент | Действие |
|---|---|
| Cold start | проверить роль + все разрешения; если чего-то нет — баннер в Dialer с переходом в Настройки |
| Возврат из системных настроек | `onResume` → перепроверить, обновить UI |
| Перед `placeCall` | проверить `CALL_PHONE`; если нет — `ACTION_CALL` fallback |
| Перед записью CallLog | проверить `WRITE_CALL_LOG`; если нет — orphan-запись |

Единая точка восстановления. Пользователь не гадает, почему что-то не работает.

## Что НЕ делаем

- Не запрашиваем разрешения «на всякий случай».
- Не блокируем приложение при отказе.
- Не используем `READ_SMS` / `RECEIVE_SMS` — не нужно.
- Не запрашиваем `SYSTEM_ALERT_WINDOW` — full-screen intent достаточно.
- Не прячем отказ за тостом — только видимый баннер + диагностика.
