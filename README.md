# Dialer с поддержкой префиксов

Нативное Android-приложение «Телефон» по умолчанию, полностью заменяющее стандартную звонилку (Google Dialer), с функцией гибкого автоматического и ручного управления префиксами при исходящих вызовах.

**Тип поставки:** внутреннее корпоративное приложение. Распространение — APK / MDM. Публикация в Google Play не планируется.

## 1. Цель проекта

Разработать нативное Android-приложение (приложение «Телефон» по умолчанию), полностью заменяющее стандартную звонилку (Google Dialer), с функцией гибкого автоматического и ручного управления префиксами при исходящих вызовах.

**Тип поставки:** внутреннее корпоративное приложение. Публикация в Google Play не планируется. Распространение — APK / MDM. Это снимает требование Permissions Declaration Form и Privacy Policy для магазина.

## 2. Целевая платформа и стек технологий

- **minSdk:** Android 10 (API 29) — минимальная версия для корректной работы `ROLE_DIALER` и `CallRedirectionService`.
- **targetSdk:** актуальный на момент старта (35).
- **Язык:** Kotlin.
- **UI:** Jetpack Compose (Material 3 / Material You).
- **Архитектура:** MVVM + Clean (data / domain / ui).
- **DI:** Hilt.
- **БД:** Room.
- **Навигация:** Navigation Compose.
- **Async:** Coroutines + Flow.
- **Тесты:** JUnit5, Turbine, MockK, Compose UI Test.

**Ключевые системные API:**

| API | Назначение |
|---|---|
| `InCallService` | Полный цикл управления звонками (роль Dialer) |
| `CallRedirectionService` | Перехват и модификация исходящего номера **до** отправки в сеть |
| `TelecomManager` | `placeCall`, выбор `PhoneAccountHandle` (SIM), запрос роли |
| `RoleManager` | Запрос роли `ROLE_DIALER` |
| CallLog Provider | Чтение и запись системного журнала |
| Contacts Provider | Контакты, фото, группы |

`PROCESS_OUTGOING_CALLS` **не используется** — deprecated с API 29, заменён на `CallRedirectionService`.

## 3. Базовый функционал (аналог Google Dialer)

Информационная архитектура и UX-паттерны повторяют Google Dialer. Отличие — модуль префиксов (раздел 4).

- **Набор номера (T9 Dialer):** цифровая клавиатура с быстрым поиском по контактам (кириллица и латиница), вставка из буфера обмена. Дополнительно — программируемые кнопки быстрых префиксов.
- **Экран активного вызова (In-Call UI):** имя/фото, таймер, Hold / Mute / Speaker / DTMF / End. Индикатор активной SIM. Поддержка конференции (merge, split) — требование контракта `InCallService`.
- **Журнал вызовов (Call Log):** входящие, исходящие, пропущенные; группировка, фильтры, длительность, время. **В системный CallLog пишется исходный номер абонента (без префикса).** Применённый префикс хранится в собственной таблице `CallLogExtras` и отображается бейджем.
- **Контакты и Избранное:** синхронизация с системной адресной книгой, карточка контакта, избранное, быстрый звонок свайпом.
- **Обработка входящих:** полноэкранный UI при заблокированном экране, heads-up при разблокированном, отклонение с SMS.

**Выбор SIM:**

- До вызова — через `TelecomManager.placeCall` с явным `PhoneAccountHandle`.
- Во время вызова — только переключение аудио-маршрута. Миграция активного звонка между SIM не поддерживается платформой и не входит в scope.

## 4. Специфический функционал: управление префиксами

Главный модуль приложения, отвечающий за модификацию номера перед отправкой вызова в сеть.

### 4.1. Режимы работы

- **Автоматический (по правилам):** подстановка префикса без участия пользователя при совпадении номера с шаблоном.
- **Полуавтоматический (выбор перед звонком):** bottom sheet с вариантами набора («Напрямую» / «Через правило X»).
- **Ручной (быстрые кнопки):** программируемые кнопки на экране набора (например, `+7`, `8`, `#31#`, `9`).

### 4.2. Конструктор правил

Неограниченное количество правил. Параметры правила:

| Параметр | Описание |
|---|---|
| Название | «Рабочая АТС», «Межгород», «Скрыть номер» |
| Условие (одно или несколько, AND) | по длине номера; по начальным цифрам; по локальной метке контакта; по SIM |
| Действие с номером | **Отрезать** N первых цифр; **Добавить** префикс; **Пауза** `,` (2 сек) и `;` (ожидание) |
| Приоритет | порядок проверки, drag-and-drop |
| Включено | toggle |

**Матчинг:** правила проверяются по возрастанию приоритета, применяется первое совпавшее (first-match). Явно зафиксировать: не «все совпавшие», а первое — иначе конфликты.

**Группы контактов:** для MVP — локальная метка в БД приложения, не `ContactsContract.Groups` (аккаунт-зависимо, нестабильно). Синхронизация с системными группами — вне scope MVP.

### 4.3. Исключения и белый список

Две разные сущности, не смешивать:

| Сущность | Поведение |
|---|---|
| **Исключения** | номера / метки, к которым **никогда** не применяются правила |
| **Белый список** | номера / метки, к которым **всегда** применяется правило X (приоритет выше автоподбора) |

По умолчанию в исключениях: `112`, `101`, `102`, `103`, короткие сервисные номера. Залочены, не удаляются.

## 5. Модель данных

Room-схема.

| Таблица | Поля |
|---|---|
| `Rule` | `id`, `name`, `enabled`, `priority` (int), `actionType` (STRIP/PREPEND/STRIP_PREPEND), `actionValue`, `simSlot` (nullable) |
| `RuleCondition` | `id`, `ruleId`, `type` (LENGTH/STARTS_WITH/LABEL), `value` |
| `RuleTarget` | `id`, `ruleId`, `targetType` (NUMBER/LABEL), `targetValue` — белый список |
| `Exception` | `id`, `type` (NUMBER/LABEL), `value`, `locked` (bool) |
| `Label` | `id`, `name` — локальные метки контактов |
| `ContactLabel` | `contactId`, `labelId` |
| `CallLogExtras` | `callLogId`, `originalNumber`, `appliedRuleId`, `dialedNumber` |
| `QuickPrefix` | `id`, `value`, `order` — кнопки ручного режима |

## 6. Нефункциональные требования и UX/UI

- **Дизайн:** Material Design 3 (Material You), светлая и тёмная темы, динамические цвета.
- **Приватность:** никакой отправки данных на внешние серверы. Всё локально. Экспорт/импорт правил — JSON-файл через SAF.
- **Стабильность входящих:** `FOREGROUND_SERVICE_PHONE_CALL`, `USE_FULL_SCREEN_INTENT`. Тест-план на Xiaomi (MIUI), Samsung (One UI), Huawei (EMUI) — проверка heads-up и full-screen intent при заблокированном экране.
- **Локализация:** русский, английский. T9 — обе раскладки.

## 7. Разрешения

| Разрешение | Зачем | Когда запрашивается |
|---|---|---|
| `READ_CALL_LOG` / `WRITE_CALL_LOG` | журнал, запись исходного номера | onboarding, после выбора роли |
| `READ_CONTACTS` | T9, карточки, метки | onboarding |
| `CALL_PHONE` | `placeCall` fallback | onboarding |
| `ANSWER_PHONE_CALLS` | приём входящих через `InCallService` | onboarding |
| `READ_PHONE_STATE` | состояние SIM, `PhoneAccountHandle` | onboarding |
| `POST_NOTIFICATIONS` (API 33+) | heads-up, foreground service | onboarding |
| `USE_FULL_SCREEN_INTENT` | full-screen incoming | onboarding |
| `FOREGROUND_SERVICE_PHONE_CALL` | стабильность входящих | manifest |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | опционально, с объяснением в UI | настройки, по запросу |

`READ_CALL_LOG` в корпоративном контуре не требует Permissions Declaration Form — Play не используется.

## 8. Этапы разработки и критерии приёмки

### 8.1. MVP

Базовый функционал раздела 3 + одно простое правило «добавить префикс».

**Критерии приёмки:**

- Роль `ROLE_DIALER` запрашивается и получается.
- Исходящий на `89991234567` при правиле «отрезать 1, добавить 9» → в сеть уходит `9991234567`.
- В системном CallLog — `89991234567`, контакт сопоставлен.
- В `CallLogExtras` — `appliedRuleId`, `dialedNumber = 9991234567`.
- Входящий отображается full-screen при заблокированном экране на Xiaomi и Samsung.
- Журнал: входящие/исходящие/пропущенные, группировка.

### 8.2. Расширенная версия

Конструктор правил (все типы условий и действий), полуавтоматический выбор, белый список и исключения, быстрые кнопки, экспорт/импорт JSON.

**Критерии приёмки:**

- Правила с несколькими условиями (AND) матчатся корректно.
- First-match по приоритету; drag-and-drop меняет порядок и результат.
- Исключения блокируют применение правил (`112` → без изменений).
- Белый список применяет правило X независимо от приоритета.
- Экспорт → импорт JSON восстанавливает состояние 1:1.
- Полуавто-выбор корректно передаёт выбранное правило в `CallRedirectionService`.

### 8.3. Тестирование

- 2 SIM: выбор до вызова, индикатор во время.
- CallLog: исходный номер, бейдж префикса, сопоставление контакта.
- Xiaomi / Samsung / Huawei: входящий при заблокированном экране.
- Юнит-тесты движка правил (матчинг, приоритет, исключения).

## 9. Технические нюансы

- **CallLog-механика:** в системный `CallLog` пишется исходный номер. Префикс — в `CallLogExtras` (своя таблица, связь по `callLogId`). Постфактумная перезапись системного журнала не используется — гонка и потеря данных.
- **`CallRedirectionService`:** именно здесь происходит трансформация номера до `placeCall`. Сервис обязан вернуть `redirectCall` или `cancelCall` в пределах таймаута; зависание = сброс вызова.
- **`InCallService`:** обязателен полный контракт — audio routing, hold, merge, conference, disconnect. Без него система не даст роль.
- **`ROLE_DIALER`:** запрашивается при первом запуске и после сброса настроек. Проверять `RoleManager.isRoleAvailable` перед запросом.
